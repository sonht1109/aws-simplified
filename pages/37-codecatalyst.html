Amazon CodeCatalyst

CodeCatalyst puts source code, CI/CD workflows and developer tools together in one place. In this lesson you'll learn how it's organized (spaces, projects, blueprints, workflows, dev environments) and build a pipeline that uses the AWS CDK to create an S3 bucket from Python code, with no manual clicks after the first setup.

What is CodeCatalyst?

Amazon CodeCatalyst is a unified software development service. Instead of wiring together CodeCommit, CodeBuild and CodePipeline yourself, you get one web app at codecatalyst.aws with repositories, CI/CD, issues and cloud dev environments. It can also connect to code that already lives on GitHub.

Need a refresher on CI/CD? See Lesson 14. For what "infrastructure as code" means, see Lesson 13: CloudFormation.

The building blocks

TermWhat it is
SpaceThe top-level container for your company or team. You connect an AWS account to the space (for billing and for deploying), and people join the space.
ProjectOne piece of work inside a space, such as an app or a pipeline. It holds repos, workflows, issues and environments.
BlueprintA project template. It generates starter code, a workflow and settings for common app types. You can also start from scratch or bring your own code.
WorkflowThe CI/CD pipeline: triggers (when to run) + actions (what to run), saved as YAML in the repo.
EnvironmentA deployment target: which AWS account and which IAM role a workflow action uses (e.g. "non-production").
Dev EnvironmentA cloud-hosted coding workspace you can open in a browser IDE or connect to from your local IDE, already set up with the project's code.
Think of it like…A space is an office building, each project is a room, a blueprint is a furnished-room template, and a workflow is the robot in the room that builds and ships things whenever new code arrives.

The AWS CDK in 60 seconds

To create an S3 bucket, you can click buttons in the console. That's fine once, but tiresome if you have to do it many times a week. The AWS Cloud Development Kit (CDK) lets you describe infrastructure in a normal programming language such as Python or TypeScript. Want 10 buckets, or a change to an existing one? Edit the code and run a CDK command.

Under the hood, the CDK converts your code into a CloudFormation template and deploys it as a stack. Two commands matter:

  • cdk bootstrap: run once per account and region. It creates a helper stack called CDKToolkit with what the CDK needs to work, such as a staging bucket and IAM roles.
  • cdk deploy: builds your app into a template and creates or updates your stack.
# install the CDK CLI (needs Node.js), or: brew install aws-cdk
npm install -g aws-cdk
cdk --version

mkdir cdk-s3-bucket && cd cdk-s3-bucket
cdk init app --language python   # creates app.py, the stack file, requirements.txt, a venv and a git repo

cdk init does most of the setup for you. app.py is the entry point that loads your stack class. You only write the resource code inside the stack class:

from aws_cdk import Stack, aws_s3 as s3
from constructs import Construct

class CdkS3BucketStack(Stack):
    def __init__(self, scope: Construct, construct_id: str, **kwargs) -> None:
        super().__init__(scope, construct_id, **kwargs)

        s3.Bucket(self, "DemoBucket",
                  bucket_name="demo-cdk-codecatalyst-12345")  # must be globally unique
TipYou don't need to remember this code. The CDK API reference has a ready example for each resource and language (search "s3 Bucket", pick Python). A code assistant such as Amazon Q in VS Code can also write it from a prompt like "generate code for S3 bucket creation with bucket name …".

Push this project to a GitHub repository. Next, CodeCatalyst will run the CDK commands for you.

The pipeline we're building

Building it, step by step

  1. Connect CodeCatalyst to AWS. Sign in at codecatalyst.aws, create (or open) a space and connect your AWS account. It then appears under the space's AWS accounts. You can reach this from the console too: search "CodeCatalyst" → Spaces.
  2. Create a project. Choose Bring your own code, authorize GitHub, and pick the repo (e.g. aws-infra-pipeline). Name the project, e.g. s3-bucket-creation. The other choices are Start from scratch or a Blueprint.
  3. Create a workflow. Go to CI/CD → Workflows → Create workflow and pick the repo and branch. You can edit it visually, which is easiest for beginners, or as YAML.
  4. Add a trigger: on push to the main branch.
  5. Add the "AWS CDK bootstrap" action. Configure the compute (EC2 runner), create an environment (e.g. bucket-creation, non-production) linked to your AWS account and an IAM role (CodeCatalyst can create one), the region (us-east-1), and the CDK CLI version (match your local one).
  6. Add the "AWS CDK deploy" action. Make it depend on the bootstrap action, use the same environment and region, and set the stack name to the one in app.py (e.g. CdkS3BucketStack). If the name doesn't match, the deploy fails.
  7. Commit the workflow. It's saved to the repo as YAML, and the first run starts.

Here is roughly what the YAML view shows (simplified. The visual editor fills in exact action versions and account details):

Name: s3-bucket-workflow
SchemaVersion: "1.0"
Triggers:
  - Type: PUSH
    Branches:
      - main
Actions:
  CDKBootstrap:
    Identifier: aws/cdk-bootstrap@v2
    Inputs:
      Sources: [WorkflowSource]
    Compute:
      Type: EC2
    Environment:
      Name: bucket-creation
      Connections:
        - Name: "111122223333"            # your AWS account
          Role: CodeCatalystWorkflowDevelopmentRole
    Configuration:
      Region: us-east-1
      CdkCliVersion: "2.150.0"
  CDKDeploy:
    Identifier: aws/cdk-deploy@v2
    DependsOn: [CDKBootstrap]
    Inputs:
      Sources: [WorkflowSource]
    Compute:
      Type: EC2
    Environment:
      Name: bucket-creation
      Connections:
        - Name: "111122223333"
          Role: CodeCatalystWorkflowDevelopmentRole
    Configuration:
      StackName: CdkS3BucketStack
      Region: us-east-1
      CdkCliVersion: "2.150.0"

What you see after the run

  • The first run takes a couple of minutes because CodeCatalyst first starts a runner, the temporary machine that executes the actions.
  • In CloudFormation you now see two stacks: CDKToolkit (from bootstrap) and your bucket stack (from deploy). The bucket appears in that stack's Resources tab.
  • In S3 you see the new bucket. The CDK used CloudFormation to create it.
  • From now on, any change you push to main (another bucket, versioning, tags…) is deployed automatically. Nobody needs to touch the console.
TipTo clean up, delete the bucket stack in CloudFormation (or run cdk destroy). Leftover stacks and buckets are exactly the kind of forgotten resources covered in Lesson 36.

For a new project, AWS points to CodeBuild, CodePipeline and CodeDeploy instead. The ideas here (IaC in a repo, a pipeline that runs cdk bootstrap/cdk deploy, environments with IAM roles) work the same way in CodePipeline, GitHub Actions or Jenkins.
Interview angle"How would you make infrastructure changes repeatable and reviewable?" Keep IaC (CDK, Terraform or CloudFormation) in Git, run it from a pipeline that has its own IAM role, and trigger it on merge to main. Then nobody needs broad console access.

Check yourself

What does cdk bootstrap do?
Bootstrap prepares the account and region once. cdk deploy then creates your actual resources.
In CodeCatalyst, what tells a workflow action which AWS account and IAM role to use?
An environment links an AWS account connection and an IAM role, plus a type such as non-production.
The CDK deploy action fails with "stack not found". What should you check first?
The deploy action's stack name has to match the stack your CDK app defines.

Key takeaways

  • CodeCatalyst brings repos, CI/CD workflows, issues and dev environments together, organized as space → project.
  • Projects can start from a blueprint, from scratch, or from your own GitHub code.
  • A workflow = triggers + actions, stored as YAML. Environments give actions an AWS account and IAM role.
  • The AWS CDK writes infrastructure in Python/TypeScript and deploys it through CloudFormation. Run cdk bootstrap once, then cdk deploy.
  • The DevOps on AWS hub (Learn / Build / Explore) helps you choose services and find ready-made solution guides.
