Reducing Your AWS Bill

A surprise bill usually means a resource you forgot to delete, often in a region you weren't looking at. Here you'll learn how to read the bill, find every running resource in every region, set a budget that emails you before things get expensive, and the team habits that keep costs down.

Why bills surprise people

You can't get your cloud bill to exactly $0 while you're learning. Every time you create resources, AWS charges for them. What you can do is keep the bill small and predictable.

The usual story goes like this:

  1. You follow a tutorial and click through the console (the AWS website) to build something.
  2. You "delete everything" when you're done, but you miss one piece, like a NAT gateway or an EKS cluster.
  3. A week or a month later, AWS emails you a bill. That's when you find out something is still running.

Cleaning up by hand in the console is easy to get wrong. Resources are spread over many pages and many regions, and some are hidden behind others. The four habits below fix that.

1. Read the bill

Open Billing and Cost Management in the console. The home page shows your month-to-date cost, the total so far this month. Beginners often stop at that one graph, but it doesn't tell you what is costing money. Two places do:

Bills

Lists this month's charges by service (EC2, EKS, VPC…), and inside each service by region. This is the quickest way to answer "who is charging me, and where?"

Cost Explorer

Charts your costs over time. Group by Service or Region to see which one jumped. It's useful for spotting trends over several months.

TipNAT gateway charges are listed under the VPC or EC2 service, not under a service called "NAT". If "VPC" shows a cost you didn't expect, a NAT gateway or a public IPv4 address is usually the reason.

2. Find every resource, in every region

The console only shows one region at a time. If you built something in us-east-1 and are now looking at ap-south-1, the forgotten resource is simply not on your screen. You need a view that covers all regions.

Tag Editor (console)

Tag Editor is part of the Resource Groups & Tag Editor service. It is meant for adding tags, but it's also the easiest way to list everything you own:

  1. Open Resource Groups & Tag Editor → Tag Editor.
  2. Regions: choose All regions.
  3. Resource types: choose All supported resource types. Tag Editor doesn't support all 200+ AWS services, but it does cover the common ones that usually cost money.
  4. Click Search resources. You get one list of everything, with its region.

The list will include many things that are free, such as IAM users, security groups, and the default VPC. A VPC by itself costs nothing. The paid parts are what you attach to it, like a NAT gateway, a public IPv4 address, or EC2 instances. Look for the paid items and delete those.

Watch outDeleting in the console often fails with a dependency error, for example "this VPC still has a NAT gateway". That's useful, because it shows you what depends on what. Delete the dependent resource first, then try again.
Beginner ruleUse one region for all your practice work. Once you pick a single region in Tag Editor, the list gets much shorter and nothing hides in another region. AWS Resource Explorer is another option: once it's turned on, it can search resources across all regions from one search box.

The same thing from the CLI

If you prefer the terminal, set up the AWS CLI with aws configure using access keys from an IAM user. Don't create access keys for the root user. Then use the Resource Groups Tagging API:

# everything in one region
aws resourcegroupstaggingapi get-resources --region ap-south-1

# save it to a file so you can search it
aws resourcegroupstaggingapi get-resources --region ap-south-1 > resources.json

# loop over several regions
for r in ap-south-1 us-east-1; do
  echo "== $r =="
  aws resourcegroupstaggingapi get-resources --region "$r" \
    --query 'ResourceTagMappingList[].ResourceARN' --output text
done
NoteThis API returns resources that are tagged, or were tagged in the past. If a resource has never had a tag, it may not appear. Use Tag Editor or the Bills page to double-check. This is one more reason to tag everything (see best practices below).

4. Guard your wallet with AWS Budgets

Cleaning up fixes today's problem. A budget warns you about tomorrow's. In Billing and Cost Management → Budgets:

  • Zero spend budget emails you as soon as you spend even a cent. That sounds safe, but once you're learning real services (an EKS cluster is never free), it just sends a lot of noise.
  • Monthly cost budget is the practical choice. Set an amount, such as $10, and an email address to notify.

With the monthly cost budget template, AWS doesn't wait until you've already gone over. It emails you:

AlertFor a $10 budgetMeaning
Actual spend reaches 85%$8.50Early warning: go and check what's running.
Actual spend reaches 100%$10.00You've hit your limit.
Forecasted spend reaches 100%predicted ≥ $10At the current rate, you'll go over by the end of the month.
Watch outA budget only sends alerts. It does not stop or delete anything. You still have to act on the email. (Budgets can be set up with budget actions that apply restrictions, but that's an advanced option.)

In a company, the same feature lets you set a budget per team or per project. You can also schedule budget reports that email a regular summary to managers. DevOps and SRE engineers who look after cloud costs set these up as a matter of routine.

Best practices for teams

Infrastructure as Code, not clicks

Build resources with Terraform, CloudFormation or the AWS CDK, not by hand in the console. Then terraform destroy (or deleting the stack) removes everything it created, in the right order. There are no forgotten NAT gateways and no dependency puzzles to solve.

Least privilege

Give people only the access they need (IAM). A new developer usually needs read access, not permission to create EKS clusters or IAM users. When they need a resource, they ask the DevOps team or run an approved pipeline (for example, a Jenkins job that can only create an EC2 instance).

Tag everything

Add tags such as owner, project and env to every resource. Tag Editor and the billing tools can then filter by tag, so you can see which team or project each cost belongs to.

Automate stale-resource cleanup

Unused EBS volumes, snapshots, FSx file systems and idle EC2 instances add up. A scheduled Lambda function can find them and either email you (SNS) or delete them. That's covered in Lesson 20. AWS Config rules can flag them too.

Done well, cost optimization can save a large share of what many companies spend, because stale resources are very common.

Got a bill you can't pay?If you're a learner and genuinely forgot to delete something, contact AWS Support. Explain that you're learning and what happened. AWS often waives one-time charges for genuine cases. Don't ignore the bill or try to get around it with new accounts and cards.
NoteAzure's resource groups make cleanup simpler: you delete the group and everything inside it goes too. On AWS, IaC stacks are the closest equivalent. That's another reason to use them.

Check yourself

Your bill shows EC2 charges, but the EC2 console looks empty. What's the most likely reason?
The console shows one region at a time. Use the Bills page (by region) or Tag Editor with "All regions" to find it.
You create a $10 monthly cost budget. What happens when spending reaches $10?
Budgets notify you (at 85%, 100% and a forecast of 100%). They don't shut anything down unless you set up budget actions yourself.
Which habit best prevents "I deleted the VPC but forgot the NAT gateway"?
IaC tracks everything it created and deletes all of it in the correct dependency order.

Key takeaways

  • Use the Bills page and Cost Explorer to see costs by service and region. The month-to-date total alone doesn't tell you much.
  • Tag Editor with All regions + All supported resource types lists your resources in one place. From the CLI, use aws resourcegroupstaggingapi get-resources.
  • Learners: stick to one region. Many items (IAM users, security groups, a plain VPC) are free. NAT gateways, EKS, EC2, load balancers and IPs are not.
  • Create a monthly cost budget to get emails at 85%, 100% and when the forecast passes 100%. Budgets alert you but don't stop anything.
  • Team habits: IaC, least privilege, tagging, and automated cleanup of stale resources.
