Route 53: DNS on AWS

People type names like amazon.com, but computers connect to IP addresses. DNS is the system that translates one into the other, and Route 53 is AWS's DNS service. Here you'll learn how DNS works and the three jobs Route 53 does: registering domains, storing DNS records in hosted zones, and running health checks.

What is DNS?

DNS stands for Domain Name System. Every load balancer or server you create gets an IP address, such as 3.6.10.171. Yet you never type IP addresses to visit Amazon, Flipkart or Instagram — you type a domain name. Something has to turn the name into the IP address. That something is DNS. We say DNS resolves a domain name to an IP address.

Think of it like…Your phone's contacts list. You tap "Mom", and the phone dials the number stored for that name. You don't need to remember the number, and if Mom changes her number you just update the contact.

Why not just share the IP address?

  1. Names are easy to remember; numbers aren't. Imagine memorising an IP for every app you use.
  2. IP addresses change. Restart a server without a fixed (static) IP, or replace a load balancer, and the address can be different. The name stays the same — you only update the DNS record.

In real setups, a domain name usually points to the load balancer in your VPC, not straight to a server.

Route 53: DNS as a service

Just as EC2 gives you "compute as a service", Route 53 gives you "DNS as a service". (The name comes from port 53, the port DNS uses.)

Without it, putting an app online the traditional way means: buy a domain from a seller like GoDaddy, find hosting somewhere else, and maintain DNS records yourself. If your app already runs on AWS, Route 53 lets you do it all in one place.

In the architecture you've been drawing since Lesson 6, Route 53 sits in front of everything: the user asks Route 53 for the address of example.com, gets the load balancer's IP, and from there the request flows through the internet gateway as before.

Route 53's three main jobs

1. Domain registration

First you need to own a domain name. Search for the name you want (myapp.com taken? Try myapp.in or myapp.xyz), then buy it. With Route 53 you can:

  • Buy the domain from AWS. You pay upfront, usually per year — this part is not pay-as-you-go. Route 53 sets up the hosted zone for you.
  • Keep a domain bought elsewhere (e.g. GoDaddy years ago). Create a hosted zone in Route 53, then copy its four name server (NS) records into your registrar's settings so the internet knows Route 53 now answers for your domain.

2. Hosted zones and DNS records

A hosted zone is a container for all the DNS records of one domain — the actual "name → address" list. When a lookup arrives, Route 53 finds the hosted zone and checks its records.

  • Public hosted zone — answers questions from anywhere on the internet.
  • Private hosted zone — answers only from inside the VPCs you attach it to, handy for internal names like db.internal.

The records you'll meet most:

TypePoints a name to…Example
Aan IPv4 addressapp.example.com → 3.6.10.171
AAAAan IPv6 addressapp.example.com → 2600:1f18::1
CNAMEanother name (an alias for a name)www.example.com → example.com

TipPointing a domain at a load balancer? Use an Alias A record. A load balancer's IPs can change over time, and an alias follows them for you. A CNAME also works for subdomains, but can't be used on the bare root domain (example.com).

Each record also has a TTL (time to live): how many seconds resolvers may cache the answer. Long TTL = fewer lookups; short TTL = changes spread faster.

3. Health checks

Route 53 can regularly send requests to your endpoints (for example every 30 seconds) to see if they're alive. Say your app runs on web servers in two Availability Zones: if one stops answering, Route 53 can stop handing out its address and send everyone to the healthy one. Health checks can also trigger alarms.

Check yourself

What is the main job of DNS?
DNS resolves names like example.com to IP addresses. Spreading traffic is a load balancer's job.
You bought myapp.com on GoDaddy and want Route 53 to manage its DNS. What do you do?
The registrar must point the domain at Route 53's name servers, which serve the records in your hosted zone.
Which record type is best for pointing example.com at an AWS load balancer?
An Alias record points at AWS resources, tracks their changing IPs and works at the root domain.

Key takeaways

  • DNS resolves easy names into IP addresses, which are hard to remember and can change.
  • Route 53 is AWS's DNS service and sits in front of your load balancer.
  • Its three jobs: domain registration, hosted zones with DNS records, and health checks.
  • Common records: A, AAAA, CNAME, Alias, MX, NS, TXT. Use Alias for AWS resources.
  • Routing policies (simple, weighted, latency, failover, geolocation, multivalue) decide which answer is returned.
