ElastiCache: Redis vs Valkey

A cache can make a slow app fast by keeping frequently used data in memory. Here you'll learn how caching works, what Valkey is and why many teams are moving to it from Redis, how to create an ElastiCache Serverless cache for Valkey in a few clicks, and how to upgrade an existing Redis cache with no downtime.

What is a cache?

A cache is a small, very fast store that keeps copies of data you read often, so you don't have to fetch it from a slower place (usually a database) every time.

Think of it like…A kitchen. The database is the supermarket: it has everything, but every trip takes time. The cache is your fridge: it's small, but grabbing milk takes a second. You keep what you use most in the fridge and restock it when it runs out.

Caches like Valkey and Redis are in-memory key-value stores:

  • In-memory: data is kept in RAM, not on disk, so reads take well under a millisecond inside AWS.
  • Key-value: you store and fetch data by a name (the key), like product:42 → {"name":"Shoes","price":59}.

Cache hit, cache miss, and TTL

The most common pattern is called cache-aside (or "lazy loading"):

  • Cache hit: the key is in the cache, so the answer comes back fast.
  • Cache miss: the key isn't there. The app reads the database (slow) and then stores the result in the cache.
  • TTL (time to live): how long a cached item stays before it expires. A short TTL keeps data fresher. A long TTL gives more hits.
  • When memory fills up, the cache evicts (removes) items, usually the least recently used ones.

Caches aren't only for speeding up database reads. The same engines are also used for session storage (who's logged in), message queues and pub/sub, leaderboards and counters, and sometimes as a primary database for fast, simple data.

Redis vs Valkey: what happened?

Redis has been the most popular in-memory key-value store for years. Then its license changed:

  1. 2024: Redis moved from the permissive open-source BSD license to "source-available" licenses. These are not open source in the traditional sense, and they restrict how cloud providers can offer it.
  2. Valkey was created as a fork (a copy that continues separately) of the last open-source Redis version. It is backed by the Linux Foundation and keeps the permissive BSD license.
  3. 2025: Redis added another license option, AGPL, an open-source license with strong "share your changes" rules.

Two license changes in a short time created uncertainty. Companies don't want licensing surprises in their cache, queue or database layer. That is a big reason many have moved to Valkey.

Amazon ElastiCache

ElastiCache is AWS's managed caching service. AWS runs the servers, patching, failover and backups for you. It supports three engines: Valkey, Redis OSS and Memcached (a simpler cache without the extra data types). You can run it two ways:

Serverless

No servers or node sizes to choose. It scales automatically and you pay for data stored and requests made. AWS handles infrastructure and maintenance with no downtime. For Valkey it's priced about 33% lower than the other engines.

Node-based (self-designed)

You pick node types, the number of shards and replicas. This gives more control and predictable capacity. Valkey nodes are about 20% lower in price than the other engines.

Create a serverless Valkey cache

  1. Console → ElastiCache → Get started → choose Valkey (the recommended option).
  2. Choose Serverless → New cache. Give it a name and description, e.g. valkey-demo.
  3. Engine version: pick the latest major version (8 at the time of writing).
  4. Review the defaults: encryption in transit and at rest, the VPC/subnets, and the security groups (they must allow your app on port 6379). Click Create.
  5. Wait 2–3 minutes for status Available. Copy the endpoint.

Connect and try it

The cache lives inside your VPC, so you connect from something in that VPC. The easiest way is the cache's Connectivity and security section → Connect to cache. It opens AWS CloudShell (a browser terminal) with the valkey-cli ready. Copy the command it shows. Serverless caches require TLS:

valkey-cli -h valkey-demo-xxxxxx.serverless.use1.cache.amazonaws.com -p 6379 --tls

> PING

> SET xkey "hello elasticache"

> SET session:abc "user42" EX 60     # expires after 60 seconds (TTL)

From application code, use a client library. Valkey GLIDE is the recommended official client (Python, Java, Node.js and more), and existing Redis client libraries also work.

Benchmarking Redis OSS vs Valkey

To compare the two fairly, run the same test against a Redis OSS serverless cache and a Valkey serverless cache. The test script ran about 10,000 SET, GET and DELETE operations from an EC2 instance in the same VPC, changing only the endpoint between runs. It measured:

  • Throughput: operations per second. Higher is better.
  • p50 latency: half of all requests were faster than this (the "typical" request).
  • p90 / p99 latency: 90% / 99% of requests were faster than this. p99 shows the slow "tail" that your unluckiest users feel, which is why benchmarks focus on it.

In that test (repeated over many runs), Valkey had higher SET/GET/DELETE throughput and a better p99 latency. Treat this as one example: always benchmark with your workload before deciding.

Upgrading Redis OSS → Valkey with zero downtime

Already have an ElastiCache Redis OSS cache? You don't need to rebuild it:

  1. Open the cache in the ElastiCache console and click Upgrade to Valkey.
  2. Pick the Valkey engine version (e.g. 8) and confirm.
  3. The cache keeps serving traffic during the upgrade. When the status returns to Available, it's running Valkey.

Because Valkey is API-compatible with Redis, your app keeps using the same endpoint, commands and client code.

TipDelete test caches when you're done. Serverless caches charge for stored data and requests, so a forgotten one will show up on your bill (Lesson 36).

Key takeaways

  • A cache keeps hot data in memory. Hits are fast. Misses go to the database and then fill the cache. TTL controls how long data stays.
  • Valkey is an open-source (BSD), Linux Foundation fork of Redis. It's Redis-compatible and growing fast. Redis's license changes pushed many teams toward it.
  • ElastiCache offers Valkey, Redis OSS and Memcached, either serverless (no capacity planning) or node-based. Valkey is the recommended and cheaper engine.
  • Connect from inside the VPC (e.g. CloudShell via "Connect to cache") using valkey-cli --tls. In code, use Valkey GLIDE or a Redis client.
  • Compare with throughput and p50/p90/p99 latency. Upgrading Redis OSS → Valkey is a one-click, zero-downtime change.
