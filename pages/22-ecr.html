ECR: Container Registry

Containers need a place to live between "built on my laptop" and "running in production". This lesson gives a quick containers primer, explains what a container registry is, compares Amazon ECR with Docker Hub, and walks you through pushing your first image.

Quick primer: containers and images

Everything in this lesson (and the ECS and EKS lessons after it) is built on a few container words. Here they are in plain language:

  • Container: a lightweight package that holds your application code plus everything it needs to run (runtime, libraries, settings). It runs the same way on your laptop, a test server or production.
  • Image: the read-only template a container starts from. Think "recipe + ingredients, frozen". You build an image once and can run many containers from it.
  • Dockerfile: a text file with the steps to build an image (start from a base image like python, copy the code, install packages, set the start command).
  • Tag: a label on an image that marks its version, e.g. my-app:1.4.2 or my-app:latest.
  • Container registry: a server that stores images so others can download (pull) them. You upload with push.
  • Repository: one folder inside a registry that holds all versions (tags) of one image, e.g. demo-app-repo.
Think of it like…A registry works like a photo-sharing app for images. You post a photo from your phone, and a friend on the other side of the world can see it. You push an image from your laptop, and a server anywhere in the world can pull it.
Note"Container" doesn't have to mean "Docker". Docker made containers popular, but any tool that follows the OCI (Open Container Initiative) standard, such as Podman or Buildah, can build images that ECR stores. This lesson uses Docker commands because they are the most common.

What does ECR stand for?

E: Elastic

As with EC2, EBS and EKS, the "E" means it scales and stays available. You can store as many images as you need and pay for what you use. AWS keeps the service up.

C: Container

It stores container images (and other OCI artifacts).

R: Registry

Like Docker Hub, Quay.io, Google's registry or GitHub Container Registry (GHCR), it's a place to push and pull images.

Amazon ECR (Elastic Container Registry) is AWS's fully managed container registry. You don't run any servers. You create repositories and push images to them.

ECR vs Docker Hub

This is a classic interview question: "Which registry do you use, and why not Docker Hub?" Both store images. The difference is focus and integration.

Docker HubAmazon ECR
Default repository typePublic (anyone can pull)Private (only allowed identities can pull)
Who can log inSeparate Docker Hub accounts for every personYour existing IAM users and roles, no new accounts
Access controlDocker Hub teams/orgsIAM policies + repository policies
IntegrationWorks everywhereBuilt-in with ECS, EKS, Fargate, CodeBuild, Lambda
Support and uptimeDocker, Inc.AWS, under the same support plan as the rest of your account
Best forPublic images, personal projectsCompany/private images on AWS

Picture a company with 10,000 engineers. With Docker Hub private repos, every person needs another account, and admins must manage access in a second place. With ECR, the IAM users, roles and policies you already have simply apply to images too.

Interview angleSay you use your cloud provider's registry for private company images (ECR on AWS, Google's Artifact Registry on GCP), because it plugs into existing IAM and services. Docker Hub is great for public images. Quay.io is another popular private option.

Creating a repository

In the console, search for Elastic Container Registry and click Create repository. No sign-up is needed because you're already in your AWS account.

  • Visibility: Private (default and recommended). Public ECR repos exist too.
  • Repository name: e.g. demo-app-repo (lowercase).
  • Tag immutability: when on, nobody can push a different image over an existing tag. v1.0 will always mean the same image, which is safer for production.
  • Scan on push: ECR scans each new image for known security vulnerabilities (CVEs) and shows the results, so others can check an image before using it.

The same thing from the AWS CLI:

aws ecr create-repository \
  --repository-name demo-app-repo \
  --image-tag-mutability IMMUTABLE \
  --image-scanning-configuration scanOnPush=true \
  --region us-east-1
Watch outECR isn't free beyond the free tier. You pay for stored image data and data transfer. Delete demo repositories and images when you finish.

Pushing your first image

Open the repository and click View push commands. AWS shows the exact commands for macOS/Linux and for Windows (PowerShell). Here's what each one does.

0. Have the AWS CLI configured

The login step uses the AWS CLI, so install it and run aws configure with your access key, secret key and default region. Full setup is in Lesson 12: AWS CLI.

1. Log Docker in to ECR

aws ecr get-login-password --region us-east-1 \
  | docker login --username AWS --password-stdin 123456789012.dkr.ecr.us-east-1.amazonaws.com
  • aws ecr get-login-password asks AWS for a temporary password (valid for 12 hours) using your IAM credentials.
  • The pipe | passes that output as the input to the next command.
  • docker login normally logs in to docker.io (Docker Hub). Giving it your registry address, <account-id>.dkr.ecr.<region>.amazonaws.com, points it at ECR instead. The username is always AWS.

2. Build the image

docker build -t demo-app-repo .

3. Tag it with the repository address

docker tag demo-app-repo:latest 123456789012.dkr.ecr.us-east-1.amazonaws.com/demo-app-repo:latest

The tag tells Docker where the image belongs: registry/repository:tag. Without it, Docker wouldn't know to send the image to your ECR repo.

4. Push

docker push 123456789012.dkr.ecr.us-east-1.amazonaws.com/demo-app-repo:latest

Refresh the repository in the console and your image appears. Anyone with the right IAM permissions can now pull it from anywhere:

docker pull 123456789012.dkr.ecr.us-east-1.amazonaws.com/demo-app-repo:latest

Permissions: when docker push fails

If you use the root account in a demo, everything just works. In real life you use an IAM user or role, and it needs ECR permissions. Typical errors are "no basic auth credentials" (you didn't log in, or the 12-hour token expired) or "not authorized to perform ecr:…" (missing permissions).

  • Go to IAM → your user/role → Add permissions → Attach policies directly and search "ECR".
  • AWS managed policies such as AmazonEC2ContainerRegistryReadOnly (pull only) or AmazonEC2ContainerRegistryPowerUser (push and pull) cover most needs.
  • Follow least privilege: CI pipelines that build images need push. Servers that only run images need pull.
TipThe CI/CD project in Lesson 16 pushes to Docker Hub. You can swap it for ECR: give the CodeBuild role ECR push permissions and replace the login/push steps with the commands above.

Check yourself

What is the main reason companies on AWS prefer ECR over Docker Hub for internal images?
Docker Hub does offer private repos, but ECR plugs into the IAM setup you already have and integrates tightly with ECS, EKS and other AWS services.
In aws ecr get-login-password | docker login …, what does the pipe do?
The pipe sends the first command's output (the token) into the second command, which reads it with --password-stdin.
Which repository setting stops someone from overwriting v1.0 with a different image?
With tag immutability on, a pushed tag can't be replaced, so a version label always points to the same image.

Key takeaways

  • An image is the template, a container is a running copy, and a registry stores images in repositories by tag.
  • ECR = Elastic Container Registry: AWS's managed, scalable, private-by-default registry.
  • Pick ECR for company images on AWS (IAM integration, ECS/EKS integration, AWS support). Docker Hub suits public images.
  • The push flow: get-login-password | docker login → build → tag → push.
  • Turn on tag immutability and scan on push. Grant least-privilege ECR permissions and delete demo repos.
