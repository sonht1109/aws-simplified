EC2: Virtual Servers

EC2 lets you rent a virtual server from AWS in minutes. You'll learn what it is, why companies use it, how to pick the right type, and then launch one and deploy Jenkins on it so you can open it from your own browser.

What is EC2?

EC2 stands for Elastic Compute Cloud (two Cs, hence "EC2"). Each word means something:

Compute

A bundle of CPU, memory (RAM) and disk. In other words, a server. Each one you launch is called an instance.

Cloud

It runs in AWS's data centers, not yours. AWS uses virtualization to carve its big physical servers into many virtual machines and hands you one.

Elastic

You can scale it up or down: make it bigger, smaller, add disk, or add more instances. AWS uses "Elastic" in many service names for this reason (Elastic Load Balancing, Elastic Kubernetes Service, Elastic Beanstalk…).

So an EC2 instance is simply a virtual server you rent from AWS, which you can resize when your needs change.

Why use EC2 instead of your own servers?

You could buy physical servers, install a hypervisor, and hand out VMs yourself. Creating 1,000 VMs with a script is the easy part. The hard part comes after:

  • keeping the hardware and virtualization layer patched and upgraded,
  • checking for security problems,
  • fixing things when a server dies at 2 a.m. and developers can't work.

With EC2, AWS handles the physical hardware and the virtualization layer. Two big wins:

  1. Less maintenance. No hardware to look after.
  2. Lower cost, pay as you go. AWS buys hardware at huge scale, and you pay only while an instance runs. Nobody using the test servers at night or over the holidays? Stop them and stop paying for compute.
NoteAWS manages the hardware, but you still look after what runs inside the instance: operating system updates, installed software and your app. See the shared responsibility model in Lesson 2.

Instance types: pick the right shape

Just like buying a physical server, you choose what it's strong at. AWS groups instance types into families:

FamilyStrong atTypical usesExample
General purposeA balance of CPU, memory and networkWeb servers, dev/test, small apps, tools like Jenkinst3.micro, m7i.large
Compute optimizedMore CPU power per GB of memoryGaming servers, batch processing, ML inference, video encodingc7i.xlarge
Memory optimizedLots of RAMIn-memory databases and caches, real-time big-data analyticsr7i.2xlarge
Storage optimizedVery fast local disksLarge databases, data warehouses, log processingi4i.large
Accelerated computingGPUs or special chipsTraining ML models, graphics renderingg5.xlarge, p5.48xlarge

Throughout this course you'll use small general purpose instances. The launch steps are identical for every type; only the type you pick (and the price) changes. Bigger and specialized types cost more. AWS adds new types over time, so check the official "Amazon EC2 instance types" page when choosing for real.

Reading an instance type name

A name like m7g.2xlarge breaks down as:

  • m: the family (general purpose)
  • 7: the generation (higher = newer, usually better value)
  • g: optional attributes (here: AWS Graviton, an ARM-based processor)
  • 2xlarge: the size. Roughly, each step up (large → xlarge → 2xlarge → 4xlarge…) doubles CPU and memory.

Where does it run?

Every instance lives in a region (e.g. Mumbai, Frankfurt) and inside one Availability Zone of that region. Pick regions close to your users or required by data rules, and spread important apps across AZs.

Regions and Availability Zones are explained in Lesson 2: Introduction to AWS.

The pieces you choose at launch

AMI: the starting disk image

An AMI (Amazon Machine Image) is a template for the instance's disk: the operating system plus any pre-installed software. AWS offers AMIs for Ubuntu, Amazon Linux, Red Hat, Debian, SUSE, Windows and more, and each comes in several versions. You can also build your own AMI with your app already installed, so new servers start ready to go.

Key pair: how you log in

By default, Linux instances on AWS have password login turned off. Instead you use a key pair: two matching keys.

  • The public key is placed on the instance by AWS.
  • The private key (a .pem file) is downloaded once to your computer. Only you have it.

When you connect, the server checks that your private key matches its public key. Share the public key freely; never share the private key. AWS doesn't keep a copy, so if you lose it you can't download it again.

How to actually connect with the key (SSH, MobaXterm, PuTTY, file permissions) is covered in Lesson 5: Connecting to EC2.

Public and private IP addresses

  • Public IP: reachable from the internet. You use it to log in and to open your app from your laptop.
  • Private IP: only works inside AWS's network. Servers use it to talk to each other.

The automatic public IP changes if you stop and start the instance. (A fixed one, called an Elastic IP, is available if you need it.) Private networks and subnets are explained in Lesson 6: VPC.

Free tier and cost

Always pick options marked "Free tier eligible". Under the classic free tier, that's a small instance (t2.micro or t3.micro, depending on the region) for 750 hours per month, enough to run one instance all month. Two instances running all month use 1,500 hours, so you'd pay for the extra. Newer accounts may get a credit-based free plan instead; check what your account shows.

Stop vs terminateStop = switch off. You stop paying for compute, but the disk is kept (and storage is still billed beyond free limits). Terminate = delete the instance for good. When you finish practising, terminate what you don't need.

Hands-on: launch an instance and deploy Jenkins

Jenkins is a popular automation server (a Java web application) used for CI/CD. It makes a perfect first app for a DevOps engineer.

1. Launch the instance

  1. In the console, search for EC2, open Instances, click Launch instance.
  2. Name: e.g. my-first-instance.
  3. AMI: choose Ubuntu, a free-tier-eligible version.
  4. Instance type: the free-tier-eligible micro type.
  5. Key pair: Create new key pair, type RSA, format .pem, give it a name like aws-login. The file downloads automatically. Keep it safe.
  6. Network settings: leave the defaults for now (they allow SSH). Networking is covered properly in Lessons 6–7.
  7. Storage: the default is a small disk (about 8 GB). That's disk space, not RAM, and enough for this demo.
  8. Click Launch instance and wait until the state shows Running. Open the instance and copy its Public IPv4 address.

2. Connect to it

On Mac or Linux (or Windows PowerShell), from the folder with your key:

chmod 400 aws-login.pem
ssh -i aws-login.pem ubuntu@<PUBLIC-IP>

ubuntu is the default login name on Ubuntu AMIs. If you see "permissions are too open", the chmod line fixes it. Windows tools and every error message are explained in Lesson 5.

Once in, whoami prints ubuntu. Use sudo for admin commands (or sudo su - to become root on the server).

3. Install Java and Jenkins

# refresh the package list (always do this on a new server)
sudo apt update

# Jenkins needs Java
sudo apt install -y fontconfig openjdk-21-jre
java -version

# add the Jenkins apt repository: copy the current two commands
# (download key + add repo) from jenkins.io → Installing Jenkins → Linux → Debian/Ubuntu
sudo apt update
sudo apt install -y jenkins

# check it is running
sudo systemctl status jenkins
TipJenkins' required Java version and its repository key change over time, so always copy the repository commands from the official Jenkins install page instead of an old blog post. Also, a micro instance has only about 1 GB of RAM, so Jenkins will be slow. That's fine for a demo.

4. Open port 8080 so your browser can reach it

Jenkins listens on port 8080. Browse to http://<PUBLIC-IP>:8080 and… nothing loads. AWS blocks incoming traffic by default; only SSH was allowed at launch.

  1. Open the instance → Security tab → click its security group (the instance's firewall).
  2. Edit inbound rules (inbound = traffic coming in to the instance) → Add rule.
  3. Type Custom TCP, port 8080, source My IP. ("Anywhere IPv4", 0.0.0.0/0, also works but opens it to the whole internet.) Save.
Security groups, inbound vs outbound rules, and NACLs are explained in Lesson 7: Security Groups vs NACLs.

5. Unlock Jenkins

Reload http://<PUBLIC-IP>:8080. Jenkins asks for an initial admin password, which it saved on the server:

sudo cat /var/lib/jenkins/secrets/initialAdminPassword

Paste it in, and the Jenkins setup screen appears. You've just deployed your first application on AWS and reached it from the outside world.

When you're done, stop or terminate the instance so it doesn't eat your free hours.

Check yourself

Jenkins is running on the instance, but http://IP:8080 won't load in your browser. Most likely cause?
Incoming traffic is blocked unless a security group rule allows it. Add an inbound Custom TCP rule for port 8080.
You need to run a large in-memory cache. Which family fits best?
In-memory caches and databases need lots of RAM, which is what memory optimized types offer.
What does an AMI provide?
The AMI is the disk template. CPU and RAM come from the instance type; the key pair handles login.

Key takeaways

  • EC2 (Elastic Compute Cloud) gives you resizable virtual servers; AWS handles the hardware, you handle what runs inside.
  • Pick an instance family by workload: general purpose, compute, memory, storage or accelerated. Names read as family + generation + attributes + size.
  • A launch needs a name, an AMI (OS image), an instance type, a key pair, network settings and storage.
  • Log in with your private key over SSH; reach apps on the public IP, but only after a security group rule opens the port.
  • Stay on free-tier types and stop or terminate instances when you're done.
