Connecting to EC2 from Windows

Log into your Linux server from a Windows laptop in a few minutes, using MobaXterm, PuTTY or the SSH client built into Windows. You'll also learn how SSH keys work and how to fix the most common connection errors.

How SSH works, in one minute

SSH (Secure Shell) is the standard way to open a remote terminal on a Linux server. Everything you type is encrypted on its way across the internet. By default it uses port 22 (a port is a numbered "door" on a server; each service listens on its own).

On EC2, SSH uses the key pair you created when launching the instance (Lesson 4):

  • AWS puts the public key on the server, in the file ~/.ssh/authorized_keys of the default user.
  • You keep the private key file on your laptop.
  • When you connect, the server sends a challenge that only the matching private key can answer. The private key itself never leaves your computer.
Think of it like…The public key is a padlock you can hand out to anyone. The private key is the only key that opens it. AWS fits your padlock to the server's door; you keep the key in your pocket.

Before you connect: checklist

  1. Instance is "Running" and has a public IPv4 address. At launch, check under Network settings → Edit that "Auto-assign public IP" is enabled.
  2. SSH is allowed in the instance's security group (inbound rule for port 22, ideally from "My IP"). The launch wizard adds this by default. More in Lesson 7.
  3. You have the private key file that matches the key pair chosen at launch. It's usually in your Downloads folder.
  4. You know the default username, which depends on the AMI (see table below). It's not your AWS login.

.pem or .ppk?

When you create a key pair, AWS asks for a file format:

.pem

The standard OpenSSH format. Works with MobaXterm, the ssh command on Windows/Mac/Linux, and almost everything else. Pick this if unsure.

.ppk

PuTTY's own format. Pick it only if you'll use PuTTY. Already have a .pem? Convert it with PuTTYgen (comes with PuTTY).

Option 1: MobaXterm (recommended for Windows)

MobaXterm is a free Windows terminal with a built-in SSH client, saved sessions and a file browser. It's friendlier than PuTTY and uses .pem files directly.

  1. Search "download MobaXterm", choose the free Home Edition, and download the Installer version (easier than the portable one).
  2. The download is a .zip. Right-click → Extract All, open the extracted folder, run the installer, accept and finish.
  3. Open MobaXterm → Session → SSH.
  4. Remote host: your instance's public IP. Tick Specify username and enter ubuntu (or the right user for your AMI).
  5. Open Advanced SSH settings → tick Use private key → browse to your .pem file.
  6. Click OK. On the first connection, accept the server's host key. You're in. Try sudo apt update.

The session is saved in the left panel, so next time it's one double-click. (If you stop and start the instance, its public IP changes, so edit the session.)

Option 2: PuTTY

  1. Install PuTTY (it includes PuTTYgen).
  2. If your key is .pem: open PuTTYgen → Load (set the file filter to "All files") → pick the .pem → Save private key as .ppk.
  3. In PuTTY, set Host Name to ubuntu@<PUBLIC-IP>, port 22.
  4. Go to Connection → SSH → Auth → Credentials and choose your .ppk as the private key file.
  5. (Optional) Back in Session, give it a name and Save. Then click Open and accept the host key.

Option 3: the ssh command (no install)

Windows 10 and 11 ship with an OpenSSH client, the same ssh command Mac and Linux users have. Open PowerShell in the folder with your key:

ssh -i .\aws-login.pem ubuntu@<PUBLIC-IP>

-i means "identity file", i.e. which private key to use. Then comes username@address.

Key file permissions

SSH refuses a private key that other users on your computer could read, with a warning like "UNPROTECTED PRIVATE KEY FILE" or "permissions are too open". Lock it down so only you can read it.

Mac / Linux:

chmod 400 aws-login.pem     # owner can read; nobody else can do anything

Windows PowerShell:

icacls.exe .\aws-login.pem /reset
icacls.exe .\aws-login.pem /grant:r "$($env:USERNAME):(R)"
icacls.exe .\aws-login.pem /inheritance:r

(chmod 600 also works on Mac/Linux: owner read + write.) MobaXterm and PuTTY handle this for you.

Check yourself

You run ssh -i key.pem ec2-user@1.2.3.4 against an Ubuntu instance and get "Permission denied (publickey)". Most likely fix?
"Permission denied" means you reached the server (so the port is open) but the login was rejected. Ubuntu AMIs use ubuntu.
Which key file format does PuTTY need?
PuTTY uses its own .ppk format. MobaXterm and the ssh command use .pem directly.
The connection just hangs and then says "Connection timed out". What should you check first?
A timeout means packets aren't reaching the server at all, which is usually a firewall rule or the wrong/missing public IP.

Key takeaways

  • SSH gives you an encrypted remote terminal on port 22; EC2 uses key pairs instead of passwords.
  • The server holds the public key; you keep the private key (.pem for most tools, .ppk for PuTTY).
  • On Windows, use MobaXterm (easiest), PuTTY, or the built-in ssh in PowerShell.
  • The command is ssh -i key.pem user@public-ip, and the user depends on the AMI (ubuntu, ec2-user, admin…).
  • Lock down key permissions; "timed out" = network/firewall, "permission denied" = wrong user or key.
