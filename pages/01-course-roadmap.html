Course Roadmap: AWS for DevOps

A map of the whole course: what you will learn, in what order, and why each piece matters for someone who wants to work as a DevOps engineer on AWS.

Who this course is for

This course teaches AWS (Amazon Web Services) from zero, through the eyes of a DevOps engineer. You do not need any earlier knowledge of AWS or any other cloud provider.

  • Goal: job-ready skills, not a certificate. The focus is on what DevOps engineers actually do every day, not on memorising exam facts.
  • Theory + practice. Most lessons explain the idea first, then walk through a hands-on demo in the AWS console or terminal.
  • Projects and interview questions appear along the way, so you can talk about real work in interviews.
  • DevOps services only. AWS has 200+ services. We skip areas like machine learning and focus on the services a DevOps engineer uses most.
Good newsCloud concepts carry over. If you learn AWS well, moving to Azure or Google Cloud later is mostly about learning new names for the same ideas. Interviewers know this, so being strong in one cloud is enough to start.

What does a DevOps engineer do on AWS?

A DevOps engineer sits between the people who write code (developers) and the systems that run it. On AWS, the day-to-day work usually looks like this:

Control access

Create users and groups, give each person only the permissions they need, and keep the main (root) account locked away.

Run servers

Launch virtual servers, install tools and applications on them (for example Jenkins), and make them reachable.

Design the network

Build private networks, decide what is public and what is hidden, and add firewalls so only the right traffic gets in.

Automate everything

Write templates and scripts so infrastructure is created by code, and build pipelines that test and deploy code automatically.

Watch and react

Monitor CPU, logs and errors, set alarms, and trigger small functions that fix or report problems automatically.

Keep it safe and cheap

Store passwords securely, check that resources follow company rules, and clean up anything that wastes money.

Notice that you rarely "just deploy an app". Around every application you also set up access, networking, security, DNS, monitoring and automation. That is why this course covers all of them.

The roadmap at a glance

Lessons build on each other. Early lessons give you an account and the basics; later lessons combine them into real projects.

Stage by stage

  1. Foundations (Lesson 2). What "the cloud" is, private vs public cloud, why companies move to AWS, regions, and creating your own AWS account that you will use for the rest of the course.
  2. IAM (Lesson 3). The first real service. You learn how to create users, groups and permissions so that nobody shares the all-powerful root login.
  3. EC2 (Lessons 4–5). Launch a virtual server, log into it, install Jenkins, and open it from your laptop's browser. Your first deployed application.
  4. Networking and security (Lessons 6–8). Private networks (VPC), firewalls (security groups and NACLs) and DNS (Route 53). Many people find this the hardest part, so it is taught in a cloud-neutral way that also makes sense on other clouds.
  5. First production-style project (Lesson 9) and interview scenarios (Lesson 10). Combine everything so far, the way a real team would.
  6. Storage and tooling (Lessons 11–13). S3 object storage and static websites, the AWS CLI, and Infrastructure as Code with CloudFormation, so you stop clicking and start scripting.
  7. CI/CD (Lessons 14–17). Build a full pipeline with AWS's developer tools: source, build, deploy.
  8. Monitoring, serverless and delivery (Lessons 18–21). CloudWatch alarms, Lambda functions, an automated cost-saving project, and CloudFront.
  9. Containers (Lessons 22–24). Store images in ECR, run them on ECS, and go deeper on Kubernetes with EKS, which most companies use.
  10. Going further (Lessons 25–40). Secrets management, Terraform, compliance checks, load balancers, migration strategies, career tips, and bigger end-to-end projects.
Don't skip around too earlySome lessons are deliberately linked. For example the CI/CD lessons (14–17) build one pipeline across four lessons, and the monitoring and Lambda lessons feed into the cost project. Skipping one can break the flow of a project.

How to get the most out of it

  • Do every practical yourself. Watching is not the same as clicking through the console and hitting your first error.
  • Stay in the free tier and clean up. Stop or delete what you create after each lesson. A forgotten server is the most common surprise bill (see Lesson 36).
  • Keep notes and turn projects into resume points. The projects (Lessons 9, 16–17, 20, 24, 26, 32–34) are designed to be discussed in interviews.
  • Practise explaining. Interviews often ask "how would you…" scenario questions. After each lesson, try explaining the "why" out loud.

Check yourself

What is the main focus of this course?
The course is built around what DevOps engineers do every day, not exam preparation or every possible service.
Which service do you learn first after creating your account, and why?
Access comes first. Once you have your own IAM user with the right permissions, every other service can be used safely.
You know AWS well but a job uses Azure. How big a problem is that?
Concepts like virtual servers, private networks, access control and pipelines exist on every cloud. Interviewers usually accept strong experience in one cloud.

Key takeaways

  • The course starts from zero and is aimed at DevOps jobs, not certificates.
  • A DevOps engineer on AWS handles access, servers, networking, automation, monitoring, security and cost, not just "deploying apps".
  • The order matters: account → IAM → EC2 → networking → storage/IaC → CI/CD → monitoring/serverless → containers → advanced projects.
  • No AWS knowledge is needed; basic Linux and Git will help a lot.
  • Practise every demo yourself and clean up afterwards to avoid surprise bills.
